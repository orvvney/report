# Гистограмма общей стоимости заключённых сделок

Статус: готова к реализации

## Контекст и цель

Подготовить страницу отчёта на Vue.js и Tailwind CSS с вертикальной столбчатой
диаграммой стоимости сделок для руководителей компании.
График и его API ещё не реализованы. По отдельному поручению пользователя
уже добавлен локальный HTTP-сервер для стартового HTML.

Проверенный контекст проекта:

- [index.html](../index.html) — стартовая текстовая заглушка.
- [package.json](../package.json) — Vue и Tailwind пока не подключены;
  команда `npm start` запускает [server.js](../server.js), команды сборки пока нет.
- `server.js` слушает `127.0.0.1:3000` (порт переопределяется через `PORT`)
  и отдаёт `index.html` для `GET`/`HEAD` по `/` и `/index.html`.
  Остальные пути и методы возвращают 404; файлы проекта не раздаются.
- [src/bitrix24/deals.cjs](../src/bitrix24/deals.cjs) читает все страницы сделок
  воронки `Վաճառք`, стадии `Կնքված`, без ограничения по дате.
  Пользовательские поля находятся по точным названиям метаданных.
- `Ընդհանուր արժեք` соответствует системному `opportunity`, валюта — `currencyId`.
  Комнатность и дата берутся из пользовательских полей `Սենյակների քանակ`
  и `Կնքման ամսաթիվ`; системную дату закрытия вместо них не использовать.
- По [документации интеграции](../docs/bitrix24.md), при прошлой живой проверке
  получены 503 сделки, типы комнатности и даты — `integer` и `date`, валюта — AMD.
  Эти сведения не являются фиксированными данными будущего отчёта.
- Браузерного API Битрикс24 пока нет. Вебхук остаётся на сервере;
  существующую локальную настройку не переносить в клиентскую сборку.

## Объём задачи

Реализовать страницу Vue + Tailwind, агрегацию сделок, серверное API чтения
Битрикс24, два режима одного графика и окно проблемных сделок. Расширить
существующий `server.js` и сохранить запуск через `npm start`. Подключить
необходимую сборку, автоматические тесты и обновить документацию.

Размещение в интернете, доступ сотрудников по сети, авторизация, изменение CRM,
выбор другого года, экспорт отчёта, поиск по проблемным сделкам и автообновление
в эту задачу не входят. Сервер работает локально на `127.0.0.1`.

## Требования

1. Использовать Vue.js и Tailwind CSS. В задачу входит рабочая страница с загрузкой
   актуальных данных Битрикс24 через серверную часть.
   В блоке находится один график. При открытии страницы выбран вариант по комнатам.
   Сверху по центру блока расположен переключатель из двух кнопок с точными
   подписями `Սենյակների քանակ` / `Կնքման ամսաթիվ`.
2. Вариант по комнатам: X — `Սենյակների քանակ`, целые категории от 1 до
   максимальной комнатности в сделках за всё время. Например, при максимуме 6
   показать 1, 2, 3, 4, 5, 6. Y — `Ընդհանուր արժեք`, сумма стоимости сделок
   соответствующей комнатности, а не их количество.
3. Вариант по месяцам: X — `Կնքման ամսաթիվ`, показать все 12 месяцев текущего года;
   Y — сумма стоимости сделок соответствующего месяца текущего года.
   Пользователь выбрал текущий год; выбор другого года не запрошен.
   Текущий год определять по часовому поясу `Asia/Yerevan`.
4. Сделки без комнатности или даты должны быть доступны через кнопку в правом
   нижнем углу блока графика. Кнопка открывает окно с информацией о таких сделках.
   Список общий для обоих режимов и включает сделки целевой воронки и стадии
   за всё время, независимо от года и активного графика.
   В каждой строке только ID со ссылкой на сделку в Битрикс24 и указание
   пропущенных полей. Сделку без обоих полей показывать один раз с указанием
   обоих полей. Название сделки, сумму и остальные значения в окно не добавлять.
   На кнопке показывать количество уникальных проблемных сделок; если их нет,
   скрывать кнопку. Пропуск комнатности исключает сделку только из графика
   по комнатам, пропуск даты — только из графика по месяцам. Если другое поле
   заполнено, учитывать сделку в соответствующем графике с учётом его периода.
5. Весь интерфейс на армянском. Суммы в AMD: на оси Y сокращённые значения,
   в подсказке при наведении или нажатии на столбец — полная сумма и количество
   сделок соответствующей категории.
6. Загружать данные при открытии страницы и по кнопке обновления в правом верхнем
   углу блока графика. Автоматического обновления нет. Переключение графика
   использует уже загруженные данные и не вызывает нового чтения Битрикс24.
7. Открывать страницу через локальный HTTP-сервер `server.js`, запускаемый
   через `package.json`: `npm start`, адрес по умолчанию `http://127.0.0.1:3000`.
   Это окончательное решение пользователя заменяет открытие через `file://`.
   HTML и API должны работать с одного origin; секрет вебхука остаётся в
   существующей серверной настройке `.env`/окружении.
8. Некорректную комнатность (в том числе 0, отрицательную или дробную) исключать
   только из графика по комнатам; некорректную дату — только из графика по месяцам.
   Отсутствующая или некорректная сумма, сумма **0**, отрицательная сумма,
   отсутствующая валюта или валюта не AMD исключают сделку из обоих графиков.
   Каждая такая сделка входит в общий список проблем за всё время; рядом с ID
   перечисляются причины. Не подменять некорректные значения нулями и не
   выполнять конвертацию валют. Счётчик учитывает уникальные сделки, а не причины.
9. Пользователь делегировал оформление, точные армянские тексты и способ
   рисования графика в предложенных границах: светлый блок, на узком экране
   горизонтальная прокрутка только области графика, окно списка прокручивается
   по высоте, закрывается крестиком, Escape или нажатием вне окна.
   Ссылки на сделки открываются в новой вкладке.

## Детали, выбранные в рамках делегирования

- Светлый фон страницы, белый блок с неброской границей, синие столбцы;
  активный режим визуально выделен. Реализация диаграммы — SVG внутри Vue,
  оформление Tailwind; отдельная библиотека графиков не требуется.
- На широком экране переключатель центрирован относительно блока,
  обновление расположено справа сверху. На узком экране обновление остаётся
  в верхнем правом углу, переключатель переносится на отдельную строку по центру;
  кнопки не перекрываются. Прокрутка графика не уносит кнопки за пределы экрана.
- Ось Y начинается с 0, подпись — `Ընդհանուր արժեք (AMD)`; масштаб определяется
  текущими суммами. Сокращения: `հազ.` для тысяч, `մլն` для миллионов,
  `մլրդ` для миллиардов. Подсказка содержит категорию, `Ընդհանուր արժեք`
  с полной суммой и `Գործարքների քանակ` с количеством учтённых сделок.
  Суммы агрегировать без предварительного округления и без видимых артефактов
  двоичной арифметики; дробную часть полного значения не обрезать.
- Месяцы по порядку: `Հունվար`, `Փետրվար`, `Մարտ`, `Ապրիլ`, `Մայիս`, `Հունիս`,
  `Հուլիս`, `Օգոստոս`, `Սեպտեմբեր`, `Հոկտեմբեր`, `Նոյեմբեր`, `Դեկտեմբեր`.
  Выбранный текущий год показывать в месячном режиме рядом с графиком.
- Отсутствующие категории между 1 и максимальной допустимой комнатностью
  имеют сумму 0. Максимум определяется по всем допустимым значениям комнатности
  целевой выборки, даже если у соответствующей сделки некорректна сумма.
  Нулевая высота пустого столбца допустима; это не нулевая сумма исходной сделки.
- Месяцы без подходящих сделок имеют сумму 0. В месячном режиме даже при пустой
  выборке остаются все 12 месяцев. Если нет ни одной сделки для текущего режима,
  дополнительно выводится `Տվյալներ չկան` (нет данных). При отсутствии допустимой
  комнатности не выдумывать верхний предел оси X.
- Кнопка обновления: `Թարմացնել`, загрузка: `Տվյալները բեռնվում են…`,
  ошибка загрузки: `Չհաջողվեց բեռնել տվյալները։ Փորձեք կրկին։`.
  Заголовок списка: `Խնդրահարույց գործարքներ`; кнопка списка содержит этот текст
  и число уникальных сделок. Пропущенное поле обозначается `Լրացված չէ`,
  некорректное — `Անվավեր արժեք`, рядом точное название поля;
  для валюты — `Արժույթ`, причина неподдерживаемой валюты — `Աջակցվում է միայն AMD`.
- Даты группируются по календарному значению пользовательского поля типа `date`,
  без сдвига дня часовым поясом браузера. `Asia/Yerevan` используется для определения
  текущего года. После явного обновления год вычисляется заново.
- При обновлении сохранять активный режим; закрывать прежнюю подсказку и окно
  списка. На время запроса скрывать старые данные и показывать загрузку,
  повторное нажатие обновления блокировать до завершения запроса.
  При ошибке не показывать частичную или старую выборку как актуальный отчёт;
  оставлять сообщение и доступную кнопку обновления для повторной попытки.
- Список сортируется по ID по возрастанию, все строки доступны прокруткой,
  поиск и пагинация не добавляются. Модальное окно удерживает клавиатурный фокус,
  после закрытия возвращает его на кнопку списка. Столбцы доступны с клавиатуры,
  подсказку можно открыть фокусом, наведением или нажатием.
- Пустые значения: отсутствующее свойство, `null`, пустая или пробельная строка.
  Числовые строки API допускаются после строгой проверки всего значения;
  boolean, массивы и объекты не преобразуются в числа. Комнатность — положительное
  безопасное целое; сумма — конечное строго положительное десятичное число.
  Дата должна быть существующей календарной датой в формате поля CRM; неверную
  дату не нормализовать автоматически в следующий месяц.
  Значение `0` суммы показывать как некорректное, а не как незаполненное.

## План реализации

1. Подключить сборку Vue и Tailwind с зафиксированными совместимыми версиями.
   Сохранить существующие команды и зависимости тестов. Добавить `npm run build`;
   описать воспроизводимый путь `npm ci` → `npm run build` → `npm start`.
   Клиентскую сборку складывать в `dist/`. Расширить `server.js` для выдачи
   HTML и ассетов только из публичной сборки, сохранив запрет доступа к корню,
   `.env`, исходникам и Git. Если сборки нет, выводить понятную инструкцию сборки.
2. Добавить серверную загрузку отчёта, переиспользовав
   [конфигурацию](../src/bitrix24/config.cjs),
   [HTTP-клиент](../src/bitrix24/client.cjs) и
   [getDeals](../src/bitrix24/deals.cjs). Сохранить точный поиск `Վաճառք`/`Կնքված`,
   `useOriginalUfNames: 'N'`, все страницы и поведение CLI `bitrix:check`.
   Не считать число 503 константой. Загружать отчёт заново на каждый явный запрос,
   без постоянного хранения и фонового обновления.
3. Выделить чистые функции нормализации, валидации, агрегации и списка проблем.
   Для обоих режимов считать суммы и количество включённых сделок;
   построить уникальный список ID с причинами за всё время.
   Текущий год определять на сервере по `Asia/Yerevan` для каждого снимка.
4. Добавить **новый** маршрут `GET /api/report`. Это планируемый контракт:
   JSON содержит год отчёта, категории по комнатам и 12 месяцев с суммой
   и количеством, а также список `{id, url, reasons}`. Причины содержат
   идентификатор поля и код пропуска/некорректного значения/валюты для перевода UI.
   Все части ответа относятся к одной полностью загруженной выборке.
   Конкретные имена остальных JSON-полей зафиксировать вместе с API-тестами.
   Успех, включая пустую выборку, — HTTP 200; ошибки конфигурации — 500;
   ошибки чтения CRM — 502. Ошибки возвращают безопасный код без URL вебхука,
   токена, сырого ответа CRM или stack trace. Ответы отчёта не кешируются.
5. Формировать ссылки на карточки сделок на сервере из HTTPS-origin портала
   и проверенного числового ID; путь вебхука и токен в ссылки не включать.
   При реализации проверить фактический путь карточки в используемом портале;
   стандартный кандидат — `/crm/deal/details/<ID>/`, пока не проверен в этой
   подготовке. Это техническая проверка интеграции, а не дополнительное решение
   пользователя. Ссылки открывать с `target="_blank"` и `rel="noopener noreferrer"`.
6. Заменить заглушку Vue-страницей: блок графика, переключатель, кнопка обновления,
   SVG-столбцы и подсказки, окно списка, доступность и согласованные состояния.
   Подключить страницу к `/api/report`; оба графика используют один ответ.
7. Написать unit/API/e2e по сценариям ниже. E2e должны запускать реальную сборку
   и `server.js`; подменять только внешний транспорт Битрикс24 искусственными
   ответами. Сохранить регрессионные проверки CLI и недоступности файлов проекта.
8. Выполнить сборку и полный `npm test`, исправить регрессии, проверить страницу
   вручную на широком и узком экране. Если обязательную проверку завершить
   невозможно, уведомить пользователя: такая сдача не считается успешной.
9. После успешных проверок запустить `docs-maintainer`, дождаться обновления
   `docs/`, проверить ссылки корневого навигатора и результат документатора.

## Критерии приёмки и обязательные сценарии тестирования

Все сценарии используют искусственные записи целевой стадии и воронки.
Зафиксировать часы, например текущий год 2026 в Ереване; использовать даты 2025
и 2026, отсутствующие поля и ошибочные значения. Автотесты не читают рабочий `.env`
и не обращаются к реальному порталу. API-проверки можно выполнять в существующем
Jest-проекте без добавления отдельного раннера.

- К0: при открытии страницы активен режим по комнатам; две кнопки переключателя
  расположены сверху по центру блока. E2e: открыть страницу на искусственных
  данных внешнего API, проверить начальный режим, переключиться на месяцы и
  обратно; подписи осей и данные соответствуют выбранному режиму.
- К1: стоимость суммируется по комнатности. Unit: две двухкомнатные сделки
  стоимостью 10 и 25 дают столбец 35; шестикомнатная сделка задаёт предел X = 6.
  E2e: пользователь видит категории от 1 до 6 и рассчитанную сумму.
- К2: месячная диаграмма всегда содержит январь–декабрь. Unit и e2e:
  воспроизводимая выборка с данными только нескольких месяцев текущего года
  и сделками прошлого года; проверить присутствие всех 12 категорий,
  исключение прошлого года из месячных сумм и его включение в суммы по комнатам.
- К3: доступен просмотр сделок с незаполненными полями. E2e: подготовить сделки
  без комнатности (в том числе с датой прошлого года), без даты и без обоих
  полей; открыть кнопку в каждом режиме. В обоих случаях список одинаковый,
  содержит все эти сделки без дублей, ID со ссылками и названия пропущенных полей.
  Проверить закрытие окна. Ссылки проверять без обращения к рабочей CRM.
- К4: счётчик отражает уникальные сделки с пропусками; при отсутствии таких
  сделок и иных проблем данных кнопки нет. Unit и e2e: сравнить выборки с нулём проблем, одной сделкой
  без обоих полей и несколькими сделками с разными пропусками.
- К5: пропуск одного поля не исключает сделку из другого графика. Unit:
  сделка без даты с комнатностью 2 и суммой 10 добавляет 10 к двум комнатам;
  сделка без комнатности с датой текущего года и суммой 25 добавляет 25
  к соответствующему месяцу. Обе присутствуют в общем списке проблем.
- К6: обновление читает актуальную выборку. E2e: первоначальная загрузка,
  переключение режимов без нового запроса, изменение искусственного ответа CRM,
  нажатие кнопки справа сверху и проверка новых сумм и счётчика проблем.
- К7: подсказка показывает сумму AMD без сокращений и количество сделок. E2e:

## Проверка результата будущей реализации

Следовать [docs/testing.md](../docs/testing.md). Существующие команды:
`npm run test:unit`, `npm run test:e2e`, полный обязательный прогон — `npm test`.
Тесты используют искусственные данные без рабочей CRM и секретов.
Новая команда `npm run build` должна быть добавлена при реализации; на момент
подготовки ТЗ её ещё нет. E2e setup должен обеспечивать актуальную сборку,
чтобы `npm test` не проверял устаревший HTML. Новые unit-модули разместить в
`tests/unit/`, браузерные сценарии — в `tests/e2e/` по действующим соглашениям.

Точки расширения: [unit интеграции](../tests/unit/bitrix24.test.js),
[e2e страницы](../tests/e2e/home.test.js),
[запуск e2e-сервера](../tests/support/global-setup.cjs).
При добавлении приложения e2e должны запускать настоящее приложение, подменяя
только внешний Битрикс24. Сохранить проверки недоступности `.env` и файлов Git.
Включить написание тестов и исправление регрессий в план реализации.

После успешных обязательных проверок исполнитель запускает `docs-maintainer`,
дожидается обновления `docs/` и проверяет ссылки корневого навигатора до сдачи.

## Согласованные решения

- Vue.js и Tailwind CSS; реальные данные Битрикс24.
- Один график с двумя кнопками по центру сверху; начальный режим — комнаты.
- Комнаты за всё время, месяцы только текущего года; год по Еревану.
- Общий список проблем за всё время: только ID со ссылкой и причины;
  счётчик уникальных сделок, кнопка скрыта при отсутствии проблем.
- Армянский интерфейс, AMD, сокращения оси и полные значения в подсказке.
- Обновление при открытии и вручную кнопкой справа сверху, без таймера.
- Некорректные данные исключаются с объяснением; пользователь отдельно
  подчеркнул, что нулевая сумма недопустима.
- Оформление, стандартные состояния, армянские тексты и рисование графика
  пользователь явно поручил определить самостоятельно в описанных границах;
  выбранные решения зафиксированы выше.
- Последнее решение о запуске — HTTP-сервер в `server.js` с командой
  в `package.json`; сервер для заглушки уже реализован отдельно.

Открытых продуктовых вопросов нет. Реализация самого графика не начиналась.
