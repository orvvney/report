# Мгновенная фильтрация графика сделок

Статус: готова к реализации

## Контекст и цель

Добавить панель из четырёх фильтров поверх области графика. Пользователь меняет
комнатность, цену, площадь или дату и сразу видит пересчитанные суммы и количества
сделок. Одновременно ужесточить допуск квартир в отчёт: квартира с незаполненным
или некорректным обязательным полем показывается только в списке проблем.

Проверенные точки текущей реализации:

- [App.vue](../src/ui/App.vue): Vue-интерфейс, SVG-график, два режима группировки,
  загрузка при открытии и по кнопке `Թարմացնել`, модальное окно проблем.
- [aggregate.cjs](../src/report/aggregate.cjs): точные десятичные суммы AMD,
  сейчас независимый допуск по комнатности и дате, общий список проблем.
- [apartments.cjs](../src/report/apartments.cjs): отбор только `Բնակարան`.
- [deals.cjs](../src/bitrix24/deals.cjs): поле `Մակերես (մ²)` уже находится
  по точному заголовку и загружается; текущая агрегация его не использует.
- [load.cjs](../src/report/load.cjs) и [server.js](../server.js): полный снимок
  CRM и `GET /api/report`, сейчас возвращающий только агрегаты и проблемы.
- [report.md](../docs/report.md): существующие правила и HTTP-контракт.

Эта задача намеренно заменяет независимый допуск по полям группировки и расчёт
максимальной комнатности по проблемным квартирам. Старые тесты этих правил
необходимо обновить под согласованное поведение, сохранив остальные регрессии.

## Объём задачи

Входят панель фильтров, локальная фильтрация снимка, проверка площади и остальных
обязательных полей, изменение состава данных API, пересчёт графика, управление
состоянием фильтров, автоматические тесты и документация после реализации.

Сохраняются выборка воронки `Վաճառք` и стадии `Կնքված`, отбор только квартир,
работа с AMD, существующие режимы группировки, ручное обновление и безопасные
ошибки загрузки. Запись в CRM, конвертация валют, новые режимы графика,
постоянное хранение фильтров и изменение CLI не входят в задачу.

## Требования

### 1. Допуск квартир и список проблем

Сначала выполнить существующий отбор квартир, затем проверить все обязательные
значения. Другие типы недвижимости не влияют ни на график, ни на максимум комнат,
ни на список проблем.

| Значение | Правило допуска |
| --- | --- |
| `Սենյակների քանակ` | Положительное безопасное целое число; существующие допустимые числовые строки сохраняются |
| `Ընդհանուր արժեք` (`opportunity`) | Конечное положительное число или допустимая десятичная числовая строка; дроби сохраняются |
| `Մակերես (մ²)` | Конечное положительное число или допустимая десятичная числовая строка; дроби сохраняются |
| `Կնքման ամսաթիվ` | Корректная календарная дата согласно существующему `calendarDate` |
| `currencyId` | Точно `AMD`, без конвертации |

Площадь нормализовать по существующим правилам десятичных значений суммы.
Формат CRM не расширять правилом запятой для пользовательского ввода: значения
из CRM обрабатываются как сейчас суммы, включая поддерживаемую экспоненциальную
запись. Boolean, массивы, объекты, пустые строки и отсутствующие значения
не преобразовывать в допустимые числа. Нулевая и отрицательная цена/площадь,
дробная комнатность и несуществующая календарная дата недопустимы.

Если хотя бы одно значение не прошло проверку, квартиру исключить из обоих
графиков, из данных для пользовательской фильтрации и из определения максимума
комнат. Это действует и при полностью пустых диапазонах фильтров.

Квартира остаётся только в `Խնդրահարույց գործարքներ`: одна строка на ID со всеми
причинами, включая новую причину `area`. Сохранить различие `missing`/`invalid`,
проверку валюты, сортировку по ID и безопасные ссылки. Сам список и его счётчик
общие за всё время; группировка и пользовательские фильтры их не меняют.
Проблемы не содержат исходных значений полей. При отсутствии проблем кнопку
скрывать, как в текущем интерфейсе.

Пользовательское поле площади искать по точному заголовку `Մակերես (մ²)` через
уже существующие метаданные; не фиксировать UF-код портала. Отсутствие либо
неоднозначность самого поля остаётся ошибкой загрузки всего отчёта, в отличие
от незаполненного значения у отдельной квартиры.

### 2. Панель и начальное состояние

Панель накладывается на верхнюю часть области графика. Не заменять её отдельной
строкой снаружи над графиком. Существующие переключатель группировки и кнопка
обновления сохраняются. Блоки слева направо:

1. `Սենյակների քանակ` — кнопки комнатности.
2. `Ընդհանուր արժեք` — два поля «от» и «до», единица AMD.
3. `Մակերես (մ²)` — два поля «от» и «до».
4. `Կնքման ամսաթիվ` — два поля «от» и «до» со стандартным календарём браузера.

Все доступные комнаты изначально выбраны; все диапазоны пустые. Пустая граница
не ограничивает соответствующую сторону диапазона. Кнопки применения нет.
Добавить общую кнопку `Զտիչները վերակայել` («Сбросить фильтры»).

Сохранить армянский язык интерфейса. Для границ использовать подписи `Սկսած`
и `Մինչև`, связать каждое поле с названием своего фильтра и стороны диапазона.
Для неверного числа/даты показывать `Անվավեր արժեք`, для обратного диапазона —
`Սկզբնական արժեքը չպետք է գերազանցի վերջնական արժեքը`.
Кнопки комнат имеют доступное состояние выбора; ошибки связаны с полями,
все действия доступны клавиатурой, фокус видим.

На широком экране четыре блока видны в одну строку. На узком они остаются
в одну строку с собственной горизонтальной прокруткой панели. Прокрутка панели
не двигает график, а прокрутка графика не двигает панель и внешние элементы.
Страница не приобретает горизонтальную прокрутку. Поля, ошибки и кнопка сброса
доступны без обрезания; панель не должна лишать пользователя доступа к графику
и его подсказкам. Точный breakpoint определяется фактическим помещением блоков.

### 3. Комнатность и категории графика

N — максимальная комнатность среди всех допущенных квартир загруженного снимка
за всё время, до пользовательских фильтров и до ограничения месячного режима
текущим годом. Сформировать кнопки всех целых значений 1–N, включая пропуски.
Например, для допустимых комнат 1 и 3 будут кнопки 1, 2, 3.

Пользователь независимо включает и выключает значения. Нельзя отключить
последнюю выбранную комнату, пока есть доступные кнопки. Выбор единственной
категории без сделок допустим и даёт пустой результат.

В комнатном графике отображать только выбранные категории в порядке возрастания.
Отключённая категория полностью исчезает с оси. Выбранная категория, для которой
после фильтрации нет квартир, сохраняет нулевые сумму и количество. Диапазоны
цены/площади/даты не меняют набор кнопок и не уменьшают N.

Если допущенных квартир нет, N отсутствует и кнопок комнат нет. Требование
«хотя бы одна выбрана» к этому состоянию не применяется.

### 4. Диапазоны и немедленное применение

Все фильтры действуют одновременно в обоих режимах. Между блоками — логическое
«И», между выбранными комнатами — «ИЛИ». Суммы и количества рассчитываются
по одним и тем же прошедшим фильтры квартирам.

Для цены и площади:

- Допустимы целые и дробные границы с точкой либо запятой: `65.5` и `65,5`
  обозначают одно значение. Запятая здесь десятичный разделитель.
- Граница `0` допустима; отрицательные и некорректные значения дают ошибку.
- Сравнения включают обе границы; одинаковые границы разрешены.
- Не округлять значения CRM и границы до целых. Сохранить точность десятичных
  сравнений и сумм, не использовать двоичное округление для решения о попадании
  на границу диапазона.

Для даты можно выбрать любые годы, включая прошлые и будущие. Обе даты включаются
целиком. Сохраняется текущая трактовка даты CRM: для ISO datetime используется
исходная календарная часть без пересчёта часового пояса. Ввод одной границы допустим.

На каждое корректное изменение ввода или кнопки сразу пересчитывать график,
без ожидания потери фокуса, Enter или применения. Фильтровать загруженный снимок
в браузере: действия с фильтрами, сброс и переключение режима не вызывают CRM
или повторную загрузку `/api/report`. При пересчёте закрывать устаревшую подсказку.

Разделять редактируемые значения и последнее корректно применённое условие
каждого диапазона. При некорректном числе/дате, отрицательной границе либо «от»
больше «до» подсветить ошибку и оставить последнее корректное условие всего
этого диапазона. Другие фильтры продолжают работать. После исправления применить
новую пару сразу. Очистка поля снимает эту границу, если полученная пара корректна.
Промежуточный некорректный ввод не должен становиться нулём или снимать ограничение.

Месячный режим всегда содержит 12 месяцев текущего года отчёта. Год по-прежнему
определяется в `Asia/Yerevan` в момент начала загрузки снимка. Фильтр дат
дополнительно ограничивает сделки, но не расширяет и не сокращает месячную ось.
Выбор только прошлогодних дат даёт 12 нулевых месяцев и сообщение `Տվյալներ չկան`.
В комнатном режиме тот же диапазон может дать ненулевые суммы за прошлый год.
Подпись периода при активном фильтре дат должна отражать его границы, а не
утверждать, что результат показан за всё время; год месячного режима остаётся виден.

### 5. Сброс, обновление и состояния загрузки

Сброс выбирает все доступные комнаты, очищает три диапазона, их ошибки и последнее
применённое состояние, сразу восстанавливает исходный график выбранного режима.
Группировка и загруженный снимок при сбросе не меняются.

При переключении режима сохранить фильтры, введённые значения и ошибки.
При `Թարմացնել` сохранить их также. После успешного обновления:

- Пересчитать набор 1–N по новому допущенному снимку.
- Сохранить выбор оставшихся кнопок; удалить исчезнувшие значения из выбора.
- Каждую новую кнопку, которой не было в предыдущем наборе, включить автоматически.
- Если после согласования набор непуст, а выбранных значений не осталось,
  выбрать все доступные. Если набор пуст, выбор тоже пуст.
- Повторно применить сохранённые диапазоны к новым данным; ошибки ввода продолжают
  использовать последние корректные условия соответствующих диапазонов.

Полная перезагрузка страницы возвращает начальное состояние фильтров;
не сохранять их в localStorage, URL или другом постоянном хранилище.

Во время загрузки и после ошибки загрузки панель видна, но её элементы
заблокированы. Сохранить существующее скрытие старого графика и проблем,
закрытие подсказки/модального окна, блокировку обновления во время запроса
и возможность повторить обновление после ошибки. Не терять фильтры при отказе
запроса, согласовывать набор комнат только после успешного получения снимка.

При успешной загрузке без допущенных квартир кнопок комнат нет, но диапазоны
и сброс доступны; показывается `Տվյալներ չկան`. Месячная ось остаётся из 12
нулевых месяцев, комнатная пуста. При наличии проблемных квартир доступен их
общий список. Если исходные допустимые квартиры есть, но все исключены фильтрами,
кнопки сохраняются, комнатные выбранные категории и все месяцы имеют нули.

## Технический подход и контракт API

Ниже — планируемое расширение, а не описание уже реализованного контракта.
Для мгновенной фильтрации текущих агрегатов недостаточно. Сохранить существующие
верхнеуровневые поля `year`, `rooms`, `months`, `problems` и добавить `deals`:

```text
{
  year: number,
  rooms: [{ category: number, amount: string, count: number }],
  months: [{ category: number, amount: string, count: number }],
  problems: [{ id: number, url: string, reasons: [{ field: string, code: string }] }],
  deals: [{ rooms: number, amount: string, area: string, date: "YYYY-MM-DD" }]
}
```

`deals` содержит только допущенные квартиры за всё время, по одной записи на
сделку; одинаковые значения разных сделок не дедуплицируются. Это минимальные
нормализованные значения для расчёта, без полных объектов CRM, персональных
полей и вебхука. Числа `amount` и `area` — точные десятичные строки с точкой.
`rooms` и `months` содержат исходные агрегаты без пользовательских фильтров,
но уже с новым строгим допуском; клиентский расчёт без фильтров должен совпадать
с ними. `problems.reasons.field` расширяется значением `area`.

Ошибки настройки, метаданных и любой страницы CRM сохраняют существующие 500/502
и безопасные тела; частичный отчёт не возвращать. Сохраняются `Cache-Control:
no-store`, проверка ID, безопасные ссылки и отсутствие секретов в ответах.

Вынести переиспользуемые чистые десятичные сравнения, фильтрацию и агрегацию
в модуль, совместимый с серверным Node.js и сборкой Vite. Конкретное размещение
модуля — техническая деталь исполнителя; не дублировать финансовые расчёты
на сервере и клиенте и не добавлять библиотеку графиков ради этой задачи.

## Критерии приёмки

- **К1. Допуск:** неполная/некорректная квартира отсутствует в обоих графиках,
  `deals` и расчёте N; в общем списке есть все причины, включая площадь.
- **К2. Комнаты:** кнопки 1–N определяются допущенным исходным снимком;
  мультивыбор работает, последнюю кнопку отключить нельзя, отключённые категории
  отсутствуют на оси, фильтры не меняют набор кнопок.
- **К3. Числовые диапазоны:** дроби с точкой/запятой, ноль, включительные и открытые
  границы дают точные ожидаемые суммы и количества.
- **К4. Даты:** обе даты включаются целиком; оба режима используют фильтр,
  но месячная ось всегда из 12 месяцев текущего года.
- **К5. Совместное применение:** каждое корректное изменение сразу обновляет
  суммы/количества по пересечению условий без повторных HTTP/CRM-запросов.
- **К6. Ошибки ввода:** неверный ввод виден пользователю, сохраняет последнее
  корректное условие только своего диапазона; исправление сразу применяется.
- **К7. Состояние:** переключение/обновление сохраняют фильтры, изменение набора
  комнат согласуется по правилам; сброс и перезагрузка возвращают начальный выбор.
- **К8. Проблемы:** список и счётчик общие, не зависят от фильтров/режима;
  сохраняются все причины и доступность модального окна.
- **К9. Загрузка и пустота:** панель видна и блокируется при загрузке/ошибке;
  успешная пустая выборка оставляет диапазоны и сброс доступными.
- **К10. Размещение:** панель поверх верхней части графика, четыре блока в заданном
  порядке, на узком экране собственная прокрутка без прокрутки страницы;
  управление и сообщения доступны клавиатурой.
- **К11. API:** нормализованные данные достаточны для пересчёта, площадь находится
  по метаданным; точность, полная пагинация и безопасные ошибки сохранены.

## План реализации

1. Прочитать [agents.md](../agents.md), [docs/testing.md](../docs/testing.md)
   и указанные выше модули. Учесть существующие незакоммиченные изменения проекта;
   не откатывать их и не включать несвязанные правки.
2. Изменить серверную нормализацию: проверка площади, общий строгий допуск,
   причины проблем, максимум по допущенным квартирам, нормализованный `deals`.
3. Выделить чистую фильтрацию и общие точные расчёты. Обновить unit/API тесты
   новых правил и старых сценариев, для которых поведение намеренно изменилось.
4. Реализовать панель и реактивное состояние в `App.vue`, пересчёт обоих режимов,
   валидацию, сброс, сохранение при обновлении, доступность и адаптивность.
5. Дополнить e2e на настоящей сборке и существующем сервере с искусственной CRM.
   Обновить фикстуры так, чтобы обычная корректная квартира имела площадь;
   отсутствие поля задавать явно в негативных сценариях.
6. Выполнить затронутые проверки, затем полный `npm test`, включая все e2e,
   исправить регрессии. Просмотреть снимки широкого и узкого интерфейса.
7. После успешных проверок запустить `docs-maintainer`, передав корень проекта,
   границы изменений, файлы/diff, новое поведение, результаты и ограничения.
   Использовать профиль `~/.codex/agents/docs-maintainer.toml`; при недоступности
   выбора профиля прочитать его и передать инструкции обычному субагенту с
   `task_name: "docs_maintainer"`, `fork_turns: "all"`, без переопределения модели.
   Дождаться результата, проверить обновление `docs/` и ссылки корневого
   навигатора до сдачи, архивирования ТЗ или коммита.

### Воспроизводимая базовая выборка

Год снимка — 2026. Все строки ниже — квартиры с AMD и корректными уникальными ID,
кроме явно указанной парковки. Числа задавать строками там, где проверяется точность.

| ID | Комнаты | Цена | Площадь | Дата | Особенность |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 100.1 | 50 | 2026-01-01 | Допущена |
| 2 | 2 | 200.2 | 65.5 | 2026-06-15 | Допущена |
| 3 | 3 | 300.3 | 80 | 2025-12-31 | Допущена за прошлый год |
| 4 | 2 | 400.4 | 80 | 2026-12-31 | Допущена |
| 5 | 5 | 500 | отсутствует | 2026-01-01 | Только проблема площади |
| 6 | 4 | 600 | 90 | отсутствует | Только проблема даты |
| 7 | отсутствует | 700 | 100 | 2026-01-01 | Только проблема комнат |
| 8 | 6 | отсутствует | 110 | 2026-01-01 | Только проблема цены |
| 9 | 20 | 900 | 120 | 2026-01-01 | Парковка, полностью исключена |

Исходно N = 3; суммы комнат: 1 → `100.1`/1 сделка,
2 → `600.6`/2, 3 → `300.3`/1. Месяцы: январь `100.1`/1,
июнь `200.2`/1, декабрь `400.4`/1, остальные нулевые. В проблемах ID 5–8.

### Обязательные проверки

1. **К1, К8 — строгий допуск (unit/API + e2e).** Загрузить базовую выборку →
   сверить приведённые суммы, N, четыре проблемных ID и причины. Параметризованно
   заменить каждое обязательное поле на отсутствующее, пустое и некорректное
   значение → квартира отсутствует в обоих графиках и нормализованных данных.
   Для площади проверить 0, отрицательное, boolean, массив, объект; для даты —
   несуществующий день; для комнат — дробь; для цены/валюты сохранить старые
   негативные случаи. Квартира с несколькими ошибками даёт одну строку со всеми
   причинами. Корректная квартира только за прошлый/будущий год допустима и влияет
   на N, хотя не входит в месяцы текущего года.
2. **К2 — комнаты (unit + e2e).** Базовая выборка → отключить 2 → на комнатной
   оси только 1 и 3, кнопки по-прежнему 1–3; в месячном графике остаётся январь
   `100.1`/1. Отключить 3, попытаться отключить 1 → 1 остаётся выбранной.
   Отдельно оставить корректные сделки только с комнатами 1 и 3 → кнопка 2 есть;
   выбрать только её → пустые суммы при сохранении кнопок.
3. **К3 — цена (unit + e2e).** Базовая выборка, все комнаты → цена от `200,2`
   до `300.3` → ID 2 и 3, суммарно `500.5`/2. Равные границы `200.2` → только
   ID 2. Только верхняя `200.2` → ID 1 и 2; только нижняя `300.3` → ID 3 и 4.
   Нижняя 0 допустима, верхняя 0 даёт пустой результат без ошибки.
4. **К3 — площадь (unit + e2e).** Диапазон `65,5`–`80` → ID 2, 3, 4;
   `65.5`–`65,5` → только ID 2; `65`–`66` также включает ID 2 без округления.
   Проверить отдельно одну границу, ноль и снятие ограничения очисткой поля.
5. **К3, К11 — точность (unit/API).** Допущенные квартиры с ценами `0.1` и `0.2`
   → сумма `0.3`. Сохранить существующий тест больших точных десятичных строк.
   Значения площади/цены, различающиеся за точностью `Number`, с точной границей
   между ними → включается только соответствующая сторона диапазона.
6. **К4 — даты (unit + e2e).** Диапазон 2026-01-01–2026-12-31 → ID 1, 2, 4,
   сумма `700.7`/3; даты границ включены. Одна граница и её очистка работают.
   Диапазон за 2025 год → комнатный график содержит `300.3`/1, месячный —
   12 нулей и сообщение пустоты. Unit: ISO datetime в начале/конце дня сохраняет
   исходную календарную дату, високосная дата проверяется, год по Еревану
   корректен на границе UTC-года. Календарь не ограничен текущим годом.
7. **К5 — пересечение и немедленность (unit + e2e).** Выбрать только комнату 2,
   цену 150–350, площадь 60–70 и даты 2026-01-01–2026-12-31 → только ID 2,
   `200.2`/1 в комнате 2 и июне. Изменять каждое условие и проверять результат
   сразу при вводе, не вызывая blur/Enter. Счётчики запросов `/api/report` и
   чтений CRM после начальной загрузки не увеличиваются. Старая подсказка закрыта.
8. **К6 — ошибки и восстановление (unit + e2e).** Применить площадь 50–80 →
   ввести нижнюю 90 → ошибка, продолжает действовать 50–80. Изменить цену →
   она применяется совместно с прежней площадью. Исправить верхнюю на 100 →
   применяется 90–100, ошибка исчезает. Повторить для отрицательного/нечислового
   ввода, дроби в процессе набора и неверной/обратной даты. Не допускать молчаливой
   замены ошибки нулём или пустой границей.
9. **К7 — переключение, обновление и сброс (e2e + unit состояния).** Установить
   фильтры, переключить режим → значения и результат сохранены. Изменить снимок
   и нажать обновление → суммы новые, условия прежние. При старом N=3 и выборе
   {2}, новом N=5 выбор становится {2,4,5}; при выборе {3} и новом N=2 — {1,2}.
   При новом N=0 выбор пуст; при последующем появлении кнопок они включены.
   Проверить обновление при ошибочном вводе с сохранением последнего корректного
   условия. Сброс очищает ошибки/диапазоны и выбирает все комнаты без запроса;
   перезагрузка страницы загружает снимок с начальными фильтрами.
10. **К8 — общие проблемы (e2e).** На базовой выборке последовательно менять
    все фильтры, получать пустой график и переключать режим → список ID 5–8
    и его счётчик неизменны. В окне видна причина площади, нет исходных значений;
    безопасные ссылки, Escape, закрытие по фону, удержание/возврат фокуса сохранены.
11. **К9 — загрузка, отказ, пустота (e2e/API).** Задержать CRM → панель видна,
    элементы недоступны, старый график скрыт. Вызвать отказ последней страницы →
    безопасная ошибка без частичного графика, панель остаётся заблокирована;
    повторное обновление восстанавливает сохранённые фильтры. Загрузить пустую
    выборку, только парковки и только проблемные квартиры → кнопок комнат нет,
    диапазоны/сброс доступны, пустое сообщение есть; проблемы видны только
    в последнем случае. Непустой снимок, исключённый фильтрами, не удаляет кнопки.
12. **К10 — расположение и доступность (e2e + визуальная проверка).** На 1440 px
    все четыре блока в нужном порядке поверх верхней части области графика.
    На 375 px строка панели прокручивается отдельно, все поля и сброс достижимы,
    страница не прокручивается горизонтально. Прокрутить панель и график по очереди,
    сверить независимость; пройти кнопки/поля/сброс клавиатурой и проверить
    доступные названия, состояние выбора и ошибки. Сохранить и просмотреть снимки
    обоих размеров, включая отображённую ошибку и открытый календарь.
13. **К11 — API и интеграция (API/unit).** Переименовать код поля площади в фикстуре,
    сохранив заголовок → данные и фильтрация корректны. Отсутствующее/неоднозначное
    поле → 502 без частичного результата. На 51 записи проверить обе страницы,
    строгий допуск и точные исходные агрегаты, совпадающие с клиентским расчётом
    без фильтров. В `deals` только четыре предусмотренных поля и только допущенные
    квартиры; одинаковые квартиры не схлопываются. В ответах нет вебхука/секретов,
    `no-store` и безопасные 500/502 сохранены. Обычная CLI сохраняет свой прежний
    охват типов недвижимости и поведение.

## Проверка результата

Команды из корня проекта:

```sh
npm run test:unit -- --runTestsByPath tests/unit/report.test.js
npm run test:unit -- --runTestsByPath tests/unit/report-api.test.js
npm run test:e2e -- --runTestsByPath tests/e2e/report.test.js
npm test
git diff --check
```

Новые отдельные файлы тестов запускать по их фактическому пути. Перед сдачей
обязателен полный `npm test` без фильтров: все unit/API и e2e. E2e автоматически
собирает production-приложение. Для подготовки окружения предусмотрены `npm ci`
и `npm run test:install`; нужны Node.js 22.12.0+ и разрешение на локальный HTTP
и запуск Chromium. Не заменять e2e DOM-моками из-за ограничений окружения.

Все данные искусственные, часы фиксированы, рабочие `.env` и CRM не используются.
Падения исправить; если завершить проверку или исправление невозможно, уведомить
пользователя и перечислить незавершённое — это не успешная сдача. После проверок
обязателен завершённый этап `docs-maintainer` по плану выше.

## Согласованные решения

- Настоящее наложение панели на график; одна строка и отдельная прокрутка на узком экране.
- Мультивыбор комнат с минимум одной выбранной при наличии кнопок; максимум
  только по допущенным квартирам до фильтрации. Отключённые категории скрываются.
- Все фильтры действуют совместно в обоих режимах; месяцы всегда текущего года.
- Дроби разрешены и в фильтрах, и в данных. Окончательное решение отменяет раннее
  пожелание запретить дробные значения. Для ввода поддерживаются точка и запятая.
- При любой проблеме обязательного поля квартира только в общем списке проблем.
- Пустые и односторонние диапазоны, включительные границы, ноль в числовом фильтре,
  стандартный календарь без ограничения года; ошибки сохраняют последнее
  корректное условие своего диапазона.
- Сохранение фильтров при переключении/обновлении, согласование новых кнопок,
  общая кнопка сброса, сброс при полной перезагрузке страницы.
- Панель видна, но заблокирована при загрузке/ошибке; при успешной пустой выборке
  диапазоны и сброс доступны.

Открытых вопросов к пользователю нет. Постановка не означает разрешение
автоматически начинать реализацию. Функционал и тесты в ходе её подготовки
не изменялись; `npm test` на этапе подготовки не запускался.
