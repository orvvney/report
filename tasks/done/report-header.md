# Новая шапка отчёта по квартирам

Статус: готова к реализации

## Контекст и цель

Заменить три текущие надписи в верхней части страницы новой центрированной
композицией с разделителем на всю ширину окна.

Проверено по исходникам:

- [src/ui/App.vue](../src/ui/App.vue): `header` находится внутри `main`
  с `max-w-7xl`, горизонтальными отступами и верхним отступом 32/56 px.
  Сейчас в шапке три надписи: `ՎԱՃԱՌՔԻ ՎԵՐԼՈՒԾՈՒԹՅՈՒՆ`,
  `Կնքված գործարքներ`, `Գործարքների ընդհանուր արժեքը՝ ըստ սենյակների և ամսաթվի`.
- [src/ui/style.css](../src/ui/style.css): фон страницы `#F5F7FB`,
  основной цвет `#18253D`, шрифт Arial / Noto Sans Armenian / sans-serif.
- [tests/e2e/home.test.js](../tests/e2e/home.test.js): два сценария ожидают
  старый заголовок `Կնքված գործարքներ`.

При подготовке постановки браузер не запускался; текущая структура установлена
по коду. Реализация не входит в подготовку ТЗ.

## Объём задачи

Только разметка и оформление верхней шапки страницы, связанные e2e-проверки
и актуализация документации после реализации. Сохранить текущую ширину и
горизонтальные отступы блока отчёта, оформление фильтров и графика, расчёты,
API, загрузку и обработку ошибок. Не добавлять зависимости.
Адаптация новой шапки под мобильные и другие устройства в задачу не входит.

## Требования

1. Удалить все три прежние надписи шапки, включая фактически используемую
   прописную форму `ՎԱՃԱՌՔԻ ՎԵՐԼՈՒԾՈՒԹՅՈՒՆ`.
2. В самом верху по центру разместить `Հաշվետվություններ`, размер 15 CSS px.
3. Под первой надписью провести горизонтальную линию от левого до правого
   края страницы, вне ограничения ширины контейнера отчёта.
4. Под линией по центру разместить
   `ԱՆՇԱՐԺ ԳՈՒՅՔԻ՝ ԲՆԱԿԱՐԱՆՆԵՐԻ ՎԵՐԼՈՒԾՈՒԹՅՈՒՆ`,
   размер 10 CSS px, цвет `#8B98A8`. Использовать полное написание `ԳՈՒՅՔԻ`
   из пункта 3 пользовательского запроса; в пункте 4 эта строка повторена
   только для указания положения следующего заголовка.
5. Следом разместить `Կնքված բնակարանների հաշվետվություն`, размер 25 CSS px.
   Сохранить эту надпись главным заголовком страницы (`h1`).
6. Все три новые надписи центрированы и имеют жирность 700.
   Семейство шрифтов сохранить текущее. Цвет первой и последней надписей —
   `#18253D`, фон шапки — `#F5F7FB`. Линия сплошная, 1 CSS px, `#DBE4EF`.
   Верхний отступ — 16 px, промежутки перед линией и после неё — по 16 px,
   между двумя нижними надписями — 8 px, до блока фильтров — 28 px.
7. Шапка остаётся видимой при загрузке, ошибке и пустом результате отчёта,
   как и текущий статический header; при прокрутке движется вместе со страницей.
8. Размеры надписей фиксированы: 15/10/25 CSS px сверху вниз.
   Не добавлять отдельные размеры, брейкпоинты или специальную компоновку
   шапки для других устройств. Мобильная адаптация отложена пользователем.
   Существующую адаптивность остальных блоков страницы сохранить.

## Критерии приёмки

- К1: вместо трёх старых надписей отображаются три новые в указанном порядке;
  последняя является главным заголовком. Точные тексты, размеры, жирность и
  серый цвет средней надписи соответствуют требованиям.
- К2: все три надписи центрированы; линия проходит от края до края
  страницы, в том числе при окне шире контейнера отчёта. Отступы, цвета и
  оформление линии соответствуют требованию 6.
- К3: размеры надписей фиксированы и не переопределяются для других устройств.
  Блок отчёта сохраняет текущую ширину, боковые отступы и существующую
  адаптивность; имеющиеся проверки узкого экрана проходят без ослабления.
- К4: загрузка, ошибка и пустой результат не скрывают шапку; фильтрация,
  переключение графика и обновление данных сохраняют прежнее поведение.

## План реализации

1. Открыть текущую страницу на искусственных данных при ширине 1440 px,
   зафиксировать исходные границы контейнера отчёта для проверки регрессий.
2. Изменить шапку в `src/ui/App.vue` и её оформление в `src/ui/style.css`.
   Вывести полноширинную область из ограничения `max-w-7xl`, сохранив
   существующий контейнер содержимого отчёта. Исключить двойной верхний отступ.
3. Обновить оба ожидания старого заголовка в `tests/e2e/home.test.js`.
   Добавить проверки содержания, визуальных свойств и геометрии
   новой шапки в этот же набор. Использовать семантические локаторы;
   при необходимости добавить стабильный `data-testid` для декоративной линии.
4. Дополнить существующие сценарии состояний в `tests/e2e/report.test.js`
   проверкой видимости нового главного заголовка; не дублировать инфраструктуру
   фикстур или тесты расчётов.
5. Выполнить целевые проверки, визуально просмотреть снимки, затем запустить
   полный `npm test` и исправить обнаруженные регрессии.
6. После успешных проверок запустить `docs-maintainer`, передать корень проекта,
   итоговый diff, новое поведение, результаты проверок и ограничения. Дождаться
   результата, проверить обновления `docs/` и ссылки корневого навигатора
   до сдачи, архивирования ТЗ или коммита. Подготовка ТЗ этот этап не запускает.

## Сценарии тестирования

Использовать существующий Jest + Playwright/Chromium и искусственный CRM-транспорт
из [tests/support/crm-fixture.cjs](../tests/support/crm-fixture.cjs).
Рабочие данные, сеть и секреты не нужны.

1. **Новая шапка (К1, К2; e2e):** стандартная фикстура → открыть `/` при ширине
   1440 px → все новые тексты видимы в нужном порядке, старые отсутствуют,
   главный заголовок имеет точное новое имя. Проверить вычисленные размеры
   шрифтов, жирность, цвета и геометрию разделителя/надписей по итоговым требованиям.
   Повторить существующую проверку `/index.html?view=report` с новым заголовком.
2. **Геометрия и границы изменений (К2, К3; e2e и визуальный просмотр):** та же
   фикстура → открыть страницу при ширине 1440 px → линия проходит от края
   до края окна, надписи центрированы, размеры равны 15/10/25 px, отступы
   соответствуют требованию 6. Проверить границы блока отчёта относительно
   прежних правил контейнера. Сохранить снимок `test-results/header-1440.png`
   и визуально проверить оформление. При проверке diff убедиться, что
   отдельные мобильные размеры и брейкпоинты шапки не добавлены.
   Имеющиеся сценарии узкого экрана в `tests/e2e/report.test.js` выполнить
   как регрессионные проверки остальной страницы; новых требований к
   мобильному дизайну шапки не вводить.
3. **Состояния и регрессия (К4; e2e):** использовать существующие сценарии
   `tests/e2e/report.test.js` с задержкой fixture, отказом и пустым снимком →
   открыть/обновить страницу → шапка остаётся видимой во всех состояниях.
   Существующие тесты фильтров, режимов графика, обновления и независимой
   прокрутки графика продолжают проходить.

## Проверка результата

Следовать [docs/testing.md](../docs/testing.md). Подтверждённые команды:

```sh
npm run test:e2e -- --runTestsByPath tests/e2e/home.test.js
npm run test:e2e -- --runTestsByPath tests/e2e/report.test.js
npm test
git diff --check
```

E2e setup сам создаёт production-сборку и запускает локальный сервер.
При отсутствии зависимостей: `npm ci`; при отсутствии Chromium:
`npm run test:install`. Нужен Node.js 22.12.0+ и разрешение на локальный HTTP-сервер
и запуск браузера. Если обязательная проверка не завершена или ошибка не
исправлена, исполнитель сообщает об этом; результат не считается успешной сдачей.

## Согласованные решения

Из исходного запроса зафиксированы замена трёх надписей, порядок новых текстов,
размеры 15/10/25 px, жирное начертание всех новых надписей, цвет `#8B98A8`
для средней строки и линия на всю ширину страницы.

Пользователь подтвердил предложенные цвета, жирность 700, центрирование всех
трёх надписей, оформление линии и отступы из требования 6.
Итоговое решение пользователя: «пока что не адаптируем под другие устройства».
Мобильная адаптация исключена из объёма; действуют исходные размеры 15/10/25 px.
