# Контекст проекта

Выбирай документы по задаче; читать весь `docs/` не требуется.

- [Технический паспорт](docs/project.md): состояние, структура, архитектура, запуск и проверки.
- [Ведение документации](docs/documentation.md): роль `docs-maintainer` и порядок актуализации.
- [Битрикс24](docs/bitrix24.md): настройка вебхука, запуск CLI и диагностика подключения.
- [Тестирование](docs/testing.md): установка, запуск unit/e2e и правила создания тестов агентами.

После каждого изменения функционала запускай `npm test` (все unit и e2e).
Создавай тесты вместе с функционалом по правилам `docs/testing.md`.

Подробную документацию храни в `docs/`; здесь оставляй только правила и ссылки.
После реализации функционала и успешных проверок запусти субагента `docs-maintainer`.
До сдачи, коммита или следующей задачи дождись обновления документации и проверки ссылок.
Сам `docs-maintainer` повторно себя не запускает.
