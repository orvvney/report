# Вход через Google и Authenticator

Дата актуализации: 13 ноября 2026 года.

При настроенной авторизации квартирный отчёт и «Տուն Էքսպո» закрыты общим
двухшаговым входом: браузер подтверждает Google-аккаунт, затем шестизначный код
Google Authenticator. Форма и серверная логика перенесены из `reportSergo`
и подключены к текущему интерфейсу основного проекта.

## Как это выглядит для пользователя

1. Страница открывается, пока проверяется сессия, затем показывает карточку входа.
2. Кнопка Google Identity Services подтверждает аккаунт. Разрешены только адреса
   из `GOOGLE_ALLOWED_EMAILS`; остальные получают отказ `google_account_not_allowed`.
3. Первый вход показывает QR-код и setup key для Google Authenticator вместе
   с пошаговым армянским руководством (кнопка «Ինչպե՞ս սկանավորել»).
   Руководство содержит снимки экранов приложения и вариант ручного ключа.
4. Шестизначный код завершает вход. Запись в Authenticator называется `Milon Report`.
5. В общей шапке обоих разделов появляется кнопка «Ելք»; её `title` — адрес
   вошедшего аккаунта. В узком виде действия шапки занимают отдельную строку.

Сессия живёт 15 минут. Остаток присылает сервер (`expiresIn`), страница считает
его по монотонным часам: сбитые часы браузера не выбрасывают пользователя раньше
времени. Истечение сессии и ответ `401` от `/api/report` или `/api/toon-expo`
возвращают форму входа и убирают отчёт со страницы. При возврате очищаются
прежние email, код, QR/ручной ключ и состояние руководства.

## Настройка

Все четыре переменные заполняются вместе в `.env` или окружении процесса.
Пустая группа отключает авторизацию (локальный запуск и тесты), частичная —
ошибка запуска. При `NODE_ENV=production` команда `npm start` отказывается
запускаться без авторизации. Все четыре значения в [`.env.example`](../.env.example)
пустые, поэтому локальный запуск без настройки открывает оба отчёта.

| Переменная | Значение |
| --- | --- |
| `PUBLIC_ORIGIN` | Точный публичный источник браузера без пути и слеша; HTTPS в production |
| `GOOGLE_CLIENT_ID` | Client ID веб-приложения Google Identity Services |
| `GOOGLE_ALLOWED_EMAILS` | Список разрешённых адресов через запятую |
| `AUTH_ENCRYPTION_SECRET` | Отдельный секрет шифрования привязок, не менее 32 символов |

Секрет генерируется командой:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

В Google Cloud Console у выбранного OAuth-клиента в **Authorized JavaScript
origins** должен быть указан тот же `PUBLIC_ORIGIN`. Без этого кнопка Google
не отрисуется. Значения секретов в репозиторий не добавляются;
[`.env.example`](../.env.example) содержит только имена и подсказки.

## Хранение привязок

Привязки лежат в `data/auth-users.enc`: JSON с полями `iv`, `tag`, `data`,
зашифрованный AES-256-GCM на ключе `scrypt(AUTH_ENCRYPTION_SECRET)`. Ни адрес,
ни секрет TOTP не видны в файле. Запись выполняется во временный файл с правами
`0600` и атомарным переименованием. Каталог `data/` исключён из Git и должен
сохраняться между выпусками: его потеря требует повторной привязки Authenticator.

Новая привязка сохраняется только после первого верного кода. Пока код не введён,
файла нет, а выданный токен привязки живёт 10 минут. Повторная привязка для уже
подключённого аккаунта отклоняется (`409`); сброс выполняется удалением
или заменой записи в `data/auth-users.enc` вместе с остановкой сервиса.

## Cookie и токены

Куки HttpOnly, `SameSite=Strict`, `Path=/`, с флагом `Secure` при HTTPS-источнике
или в production. Значение — `base64url(JSON).HMAC-SHA256`, подпись проверяется
`timingSafeEqual`; чужой секрет, испорченная подпись, другой тип токена
и истёкший срок дают отказ.

| Cookie | Срок | Назначение |
| --- | --- | --- |
| `report_session` | 15 минут | Подтверждённая сессия с версией `sessionVersion` |
| `report_google_challenge` | 5 минут | Подтверждённый Google-аккаунт до ввода кода |
| `report_totp_enrollment` | 10 минут | Ещё не сохранённая привязка Authenticator |

Выход увеличивает `sessionVersion` в хранилище, поэтому ранее выданные сессии
того же аккаунта перестают действовать сразу.

## HTTP-контракт входа

Маршруты существуют только при настроенной авторизации; иначе `/api/auth/*`
отвечает `404` и оба отчёта открыты. Ответы `/api/auth/*` при включённой
авторизации имеют `Cache-Control: no-store`. Ошибки имеют вид
`{"error":{"code":"...","message":"..."}}`.

| Маршрут | Ответ |
| --- | --- |
| `GET /api/auth/config` | `{ googleClientId }` для инициализации кнопки Google |
| `POST /api/auth/google` | `{ email, requiresEnrollment }`, ставит cookie challenge |
| `POST /api/auth/enroll` | `{ qrCode, manualKey }`, ставит cookie привязки |
| `POST /api/auth/login` | `{ username }`, ставит сессию и снимает временные cookie |
| `GET /api/auth/me` | `{ username, expiresAt, expiresIn }` или `401` |
| `POST /api/auth/logout` | `{ ok: true }`, отзывает сессии аккаунта |

| Код | Значение |
| --- | --- |
| `401 authentication_required` | Нет действующей сессии; так же отвечают `/api/report` и `/api/toon-expo` |
| `401 google_authentication_required` | Нет подтверждённого Google-аккаунта |
| `401 invalid_google_credential` | Токен Google не прошёл проверку |
| `401 invalid_code` | Неверный или просроченный код Authenticator |
| `403 google_account_not_allowed` | Адрес отсутствует в `GOOGLE_ALLOWED_EMAILS` |
| `403 origin_not_allowed` | Заголовок `Origin` не совпал с `PUBLIC_ORIGIN` |
| `409` | Authenticator уже подключён |
| `429 too_many_attempts` | Пять неверных кодов подряд; пауза 5 минут |
| `429 too_many_requests` | Больше 20 POST-запросов Google/enroll/login за 5 минут с адреса |

`/api/report` и `/api/toon-expo` используют общий лимит 60 запросов в минуту
на аккаунт. Сессия проверяется до вызова загрузчика CRM, включая `?refresh=1`.
HTML и файлы `/assets/` остаются публичными: внутри собранного приложения
живёт сама форма входа. Успешные и неуспешные попытки пишутся в журнал процесса
строками `{"type":"audit",...}` с событием, временем, аккаунтом и адресом.
Событие `report_viewed` дополнительно содержит путь API и статус ответа.

## Устройство

- [`src/auth/config.cjs`](../src/auth/config.cjs) — чтение и проверка переменных,
  правило «всё или ничего», нормализация адресов и источника.
- [`src/auth/service.cjs`](../src/auth/service.cjs) — проверка токена Google,
  TOTP, QR-код, шифрованное хранилище, подписанные токены и cookie.
- [`src/auth/routes.cjs`](../src/auth/routes.cjs) — маршруты `/api/auth/*`,
  ограничители частоты, защита сессии и журнал аудита.
- [`server.js`](../server.js) — Express с Helmet, проверкой `Origin`,
  CSP для Google Identity Services, защитой обоих API, белым списком статики
  и сохранёнными перенаправлениями favicon. PNG/JPG руководства раздаются
  только из сборки.
- [`src/ui/AuthGate.vue`](../src/ui/AuthGate.vue) — экран входа и доступ к отчёту;
  [`src/ui/LoginGuide.vue`](../src/ui/LoginGuide.vue) — руководство со снимками;
  [`src/ui/login.css`](../src/ui/login.css) — стили, ограниченные `.auth-root`.
  [`main.js`](../src/ui/main.js) монтирует `AuthGate`, а
  [`ReportHeader.vue`](../src/ui/ReportHeader.vue) передаёт действие выхода.

Снимки экранов руководства лежат в `images/authenticator-*.png|jpg` и выпускаются
Vite в `/assets/`.

## Развёртывание

Процесс слушает только локальный интерфейс, TLS завершает обратный прокси,
а `PUBLIC_ORIGIN` совпадает с публичным адресом. Каталог `data/` должен
принадлежать пользователю сервиса и быть доступен ему на запись, иначе запуск
прервётся при создании хранилища привязок. Переменные входа задаются
в `EnvironmentFile` юнита или `.env` каталога приложения с правами на чтение
только пользователю сервиса. При выпуске новой версии `data/` сохраняется.

Автотесты заменяют Google Identity Services/проверку ID-токена и внешний
CRM-транспорт; настоящие серверные маршруты, сессия, TOTP и загрузчики работают.
