# Տուն Էքսպո

## Назначение и навигация

Раздел показывает лиды и сделки с источником `SOURCE_ID = 305` в Битрикс24.
Слева `Լիդերի մուտք` — лиды, справа `Գործարքներ` — самостоятельная выборка
сделок всех стадий и воронок, включая сделки без лида. Связь `LEAD_ID`
не участвует в отборе; процент конверсии не рассчитывается.
Доступны только записи, видимые владельцу серверного вебхука.

Пункт `Տուն Էքսպո` в общем меню открывает `/#toon-expo` в той же вкладке.
Поддерживаются прямой вход, перезагрузка и история назад/вперёд через `hashchange`.
Возврат в `Բնակարաններ` убирает hash; парковки пока только закрывают меню.
`App.vue` создаёт Expo при первом посещении, затем скрывает/показывает разделы,
сохраняя их локальное состояние. Квартирный отчёт продолжает собственную
начальную загрузку независимо от выбранного раздела.

Общий [`ReportHeader.vue`](../src/ui/ReportHeader.vue) содержит логотип,
`Հաշվետվություն`, обновление и меню. Фактические подзаголовки —
`Կնքված բնակարաններ` для квартир и `Տուն Էքսպո` для Expo (15 px).
Высота шапки от 132 px; её геометрия и отступ до содержимого совпадают
у обоих разделов. Подробности общей шапки — в [report.md](report.md#интерфейс).
Отдельного вступительного блока с заголовком Expo над колонками нет.

## Независимые периоды и таблицы

В [`ToonExpo.vue`](../src/ui/ToonExpo.vue) две равные колонки с вертикальным
разделителем; при ширине окна до 900 px включительно лиды расположены над
сделками, разделитель горизонтальный. Таблицы прокручиваются внутри блока.
Каждая половина содержит собственный фильтр сверху, итог количества,
дневную таблицу и список записей. Общего фильтра нет.

[`ExpoPeriodFilter.vue`](../src/ui/ExpoPeriodFilter.vue) хранит состояние
отдельно для каждой половины. Контекст календаря, первая дата и диапазон
доступных лет строятся по данным именно этой половины, от первого года
до текущего включительно; для пустой выборки доступен текущий год.
И дата создания, и текущий календарный день определяются по `Asia/Yerevan`.

По умолчанию выбран текущий год. Доступны мультивыбор месяцев одного года,
мультивыбор кварталов, год, быстрый выбор и произвольный диапазон дат.
Быстрые варианты: текущий/прошлый месяц, текущий/прошлый год, последние
12 месяцев и всё время. Календарные периоды ограничены сегодняшним днём;
«последние 12 месяцев» начинаются с первого числа месяца 11 месяцев назад.
У custom-диапазона границы включительные и могут оставаться открытыми.
При неверной дате или обратном диапазоне показана ошибка, результаты этой
половины скрыты до исправления или перехода к другому режиму.

Общий [`PeriodFilter.vue`](../src/ui/PeriodFilter.vue), выделенный из `App.vue`,
задаёт интерфейс периода квартир и Expo, а [`period.cjs`](../src/report/period.cjs) —
календарную логику. [`MonthPicker.vue`](../src/ui/MonthPicker.vue) использует
уникальный `useId` для popover и `aria-controls`. Поля и ошибки
[`RangeInputs.vue`](../src/ui/RangeInputs.vue) получают отдельные префиксы
`expo-arrival-` и `expo-deals-`, поэтому ID нескольких фильтров не конфликтуют.

Фильтры применяются локально без CRM-запросов. Дневные таблицы показывают
количество записей по дате создания, по возрастанию даты, без заполнения
дней с нулём. Списки сортируются по дате убыванию, затем ID убыванию,
разбиваются на независимые страницы по 25 строк. Изменение периода сбрасывает
страницу только соответствующей половины. Ссылки открывают карточку CRM
в новой вкладке с `noopener noreferrer`.

При первой загрузке запрашивается `/api/toon-expo`; кнопка общей шапки
в Expo и повтор после ошибки используют `?refresh=1`. Пока идёт запрос,
старый снимок скрыт и кнопка обновления заблокирована. При ошибке показано
сообщение с повтором, при пустой выборке — нулевой итог и пояснение.
Успешное обновление сбрасывает обе страницы на первую; фильтры сохраняются
и согласуются с новыми данными. Автоматического обновления по таймеру нет.

## Сервер и HTTP-контракт

Настройка `BITRIX24_WEBHOOK_URL` и запуск совпадают с основным приложением:
[настройка Битрикс24](bitrix24.md#настройка-и-запуск),
[локальный запуск](project.md#установка-и-локальный-запуск).
Новых зависимостей или отдельного вебхука нет.

[`server.js`](../server.js) подключает отдельный `createExpoLoader` из
[`expo-load.cjs`](../src/report/expo-load.cjs). `GET /api/toon-expo`
возвращает полный снимок без серверных фильтров периода. Только `refresh=1`
обходит действующий кеш. Все ответы JSON имеют
`Content-Type: application/json; charset=utf-8` и `Cache-Control: no-store`.

Успешный ответ (200):

```json
{
  "sourceId": "305",
  "leads": [],
  "deals": [],
  "updatedAt": "2026-11-13T10:00:00.000Z"
}
```

Каждая запись `leads`/`deals` содержит `id` (положительное безопасное целое),
`title` (строка, при пустом заголовке `#ID`), `date` (`YYYY-MM-DD` по Еревану)
и `url` (HTTPS origin портала + `/crm/lead/details/ID/` либо
`/crm/deal/details/ID/`). `updatedAt` — время создания снимка в ISO UTC;
при выдаче из кеша оно не меняется. Полный URL вебхука клиенту не передаётся.

Загрузчик последовательно читает `crm.lead.list` и `crm.deal.list`, даже
если лидов нет. Для обоих методов параметры одинаковы:

- `filter: { "=SOURCE_ID": "305" }`, без фильтров стадии, воронки и `LEAD_ID`;
- `select: ["ID", "TITLE", "SOURCE_ID", "DATE_CREATE"]`;
- `order: { "ID": "ASC" }`, начальный `start: 0`, далее все страницы по `next`.

На странице допускается не более 50 записей. Проверяются положительные ID,
строго возрастающий порядок без повторов, продвижение `next`, точное совпадение
источника, ISO-подобная строка даты с `T` и возможность преобразования в дату.
Ошибка любой страницы или записи отклоняет весь снимок, частичный успех не выдаётся.
[`client.cjs`](../src/bitrix24/client.cjs) расширяет существующий allowlist
только этими двумя методами чтения; операции записи не добавлены.

Кеш хранится в памяти экземпляра загрузчика 5 минут отдельно по полному URL
вебхука, независимо от кеша квартир. Одновременные обращения к одному источнику
объединяются через `pending`, включая ручные обновления. Возвращается копия снимка.
Перед новым чтением старый кеш очищается; при ошибке обновления он не выдаётся.

| Статус | Тело | Причина |
| --- | --- | --- |
| 500 | `{"error":"CONFIGURATION_ERROR"}` | Ошибка настройки вебхука |
| 502 | `{"error":"CRM_READ_ERROR"}` | Ошибка чтения CRM или проверки снимка |

Ответы ошибок не содержат секретов вебхука, сырых ответов CRM или подробностей исключений.

## Проверки и ограничения

Состав unit/API и браузерных сценариев приведён в
[testing.md](testing.md#проверки-տուն-էքսպո).
По переданным исполнителем результатам полный `npm test` прошёл:
30 наборов / 600 тестов, два проекта, 69,631 секунды, exit 0;
целевой Expo e2e — 11 passed. `npm run build` и `git diff --check` прошли.
Документатор эти проверки повторно не запускал.

Проверки выполнены на синтетических данных. Реальная CRM для этого раздела
не проверялась: полнота данных под рабочими правами вебхука и фактическая
доступность источника 305 остаются неподтверждёнными.
