Дата актуализации: 21 октября 2026 года.

## 1. Общие сведения

| Параметр | Значение |
| --- | --- |
| Рабочее название | `report` — по имени каталога проекта |
| Состояние | Стартовая страница и локальная CLI-проверка Битрикс24 |
| Пользовательская точка входа | `index.html` |
| Контроль версий | Git |
| Назначение продукта | Будущий отчёт руководителям об успешных сделках компании |

Подключение к рабочему порталу и сверка полученных данных подтверждены 21 октября
2026 года. Подробности живой проверки и техническое решение по именам полей —
в инструкции интеграции; результаты полного прогона тестов — в [testing.md](testing.md).

```text

├── tests/                # Unit, браузерные e2e и общая инфраструктура
```

`index.html` содержит две текстовые строки: `test` и `hello world`. HTML-разметка, стили, клиентские скрипты и пользовательские сценарии пока отсутствуют.

## 3. Архитектура и технологии

- Текущее содержимое страницы отдаётся как статический файл; сборка не требуется.
- Фронтенд-фреймворк и UI-библиотеки не подключены.
- Постоянный backend, публичное API, база данных и авторизация не реализованы. Чтение внешнего REST API выполняет отдельная команда Node.js; она не связана со страницей.
- Интеграция использует CommonJS и встроенные `fetch` и `node:util.parseEnv`, без дополнительных runtime-зависимостей.
- Тестовый стек: Jest 30.5.2, Playwright 1.64.1 и serve-handler 6.1.7; все зависимости относятся к разработке и закреплены в `package.json` и `package-lock.json`.
- Jest запускает unit в Node.js и e2e в Chromium через библиотеку Playwright. Для e2e встроенный `node:http` поднимает сервер на свободном порту, отдающий только стартовую страницу; каждый тест получает новый контекст браузера и страницу. `serve-handler` остаётся в dev-зависимостях, но тестовый сервер его не использует.
- Контейнеризация, конфигурация CI/CD и настройки развёртывания в репозитории отсутствуют.

MCP-серверы относятся к инструментам разработки. В коде страницы нет обращений к ним.

## 4. Инструменты разработки

В `mcp.json` объявлены следующие MCP-серверы:

| Сервер | Команда запуска из конфигурации | Переданные параметры |
| --- | --- | --- |
| `chrome-devtools` | `npx -y chrome-devtools-mcp@latest` | `--isolated`, `--chromeArg=--guest`, `--chromeArg=--new-window` |
| `context7` | `npx -y @upstash/context7-mcp@latest` | Дополнительные параметры отсутствуют |

Для выполнения этих команд нужны Node.js и npm с доступной командой `npx`. `package.json` требует Node.js 22 или новее для CLI и тестового стека; точные версии Node.js и npm в проекте не закреплены. При необходимости загрузки пакетов требуется доступ к npm-реестру.

Оба пакета указаны с тегом `latest`, поэтому версия инструментов может изменяться между запусками. Наличие конфигурации само по себе не подтверждает подключение серверов к MCP-клиенту или их работоспособность; их запуск при подготовке паспорта не проверялся.

## 5. Локальный просмотр

Текущий `index.html` можно открыть непосредственно в браузере. Установка зависимостей для просмотра не нужна.

Для проверки страницы по HTTP используйте браузерные тесты: `npm run test:e2e`.
Их сервер разрешает только `GET`/`HEAD` для `/` и `/index.html`; другие пути
возвращают 404. Отдельная команда запуска веб-приложения пока не предусмотрена.

Не раздавайте корень проекта стандартным файловым HTTP-сервером
(например, `python3 -m http.server`): в корне находится локальный `.env` с вебхуком.
Правила `.gitignore` защищают от добавления файла в Git, а не от чтения по HTTP.

Для проверки CRM запустите `npm run bitrix:check` после
[локальной настройки вебхука](bitrix24.md).

## 6. Проверка изменений

После каждого изменения функционала обязателен `npm test`: он запускает все unit и e2e последовательно. Установка и правила разработки тестов, включая работу агентами, описаны в [testing.md](testing.md).

```sh
npm ci
npm run test:install
npm test
```

Unit-тесты проверяют настройку вебхука, чтение API, поиск метаданных, пагинацию, вывод CLI и безопасные ошибки на искусственных данных. E2e проверяют стартовую страницу и запрет чтения секретов и файлов проекта. Линтер, форматтер и команды сборки не настроены. Живая проверка CRM выполняется отдельно и не заменяется автотестами.

Дополнительные ручные проверки:

1. Открыть `index.html` в браузере и проверить отображение ожидаемого содержимого.
2. При изменении `mcp.json` проверить корректность JSON и запуск затронутого сервера в используемом MCP-клиенте.
3. Перед фиксацией изменений просмотреть `git diff` и `git status --short`.

## 7. Правила дальнейшей работы

- Согласовывать новую функциональность с требованиями конкретной задачи; текущий объём — только CLI-проверка API.
- Не считать инструменты из `mcp.json` зависимостями веб-страницы.
- При добавлении стека или зависимостей документировать их версии, установку, запуск и проверку.
- Создавать тесты вместе с функционалом по [правилам тестирования](testing.md); до сдачи запускать весь набор через `npm test`.
- Не добавлять секреты, токены и пароли в репозиторий. Вебхук хранится в локальном `.env`; `.env.example` содержит только пустую переменную.
- После реализации функционала и успешных проверок запускать `docs-maintainer` по [процессу актуализации документации](documentation.md). Поддерживать этот паспорт при изменении структуры, архитектуры, способов запуска или проверки проекта.
